mdtools is public: github.com/brazilofmux/mdtools (MIT)

It started with one annoyance. AI-generated markdown puts a list directly under a sentence, and Pandoc silently folds the whole thing into one paragraph. No warning — you find out from the rendered book. I wrote a small fixer. It grew from there.

Six tools now, sharing one contract (0 clean / 1 findings / 2 couldn't run, --check by default, --diff to preview, --fix to apply):

  • mdfix — structural repair. Four required fixes, the ones without which Pandoc reads something other than what you wrote. Then opt-in passes: bullet style, heading emphasis, Chicago punctuation, hard wrapping, Unicode NFC normalization.
  • mdquery — outline, block listing, section extraction, stats.
  • mdlinks — the link graph across a whole repository: broken anchors, undefined references, dead files. Suggests repairs, and applies them on request.
  • mdterms — glossary enforcement. Forbidden spellings, and acronyms used before they're defined.
  • mdcheck — the repo-wide gate. Fifteen checks of its own plus everything the others report, front-matter schema validation, and citation keys resolved against a bibliography. JSONL or SARIF, so CI ingests it directly.
  • prosevary — controlled lexical variation.

The editorial passes are opinions. They are right for my manuscripts and may be wrong for yours, so a bare mdfix runs none of them, and `-n --diagnostics` tells you exactly what a profile would change before you let it near anything. `-i` writes a .bak first — but don't lean on that instead of version control until you've run the tool over your own prose for a while.

If you have Ollama or any OpenAI-compatible endpoint running locally, prosevary generates sentence variants and then gates them: an embedding-similarity threshold and a judge model both have to agree the meaning didn't move. If the gates aren't actually live, it refuses to write.

The geeky part: it's all built on one intermediate representation.  `mdfix --emit-ir` emits block structure as JSONL with exact byte spans, and edits come back the same way, so no other tool re-implements Markdown grammar. That's also why it reads marker forms and layouts Pandoc treats as prose — deliberately. A list Pandoc silently reads as a paragraph is the bug; the tool has to see the intent before it can repair it into something Pandoc reads right.

1,085 tests, with Pandoc itself as the oracle over 511 files of real manuscript.
